# Changelog

All notable changes to this branch are documented in this file. Versions are listed newest first.

# 2026.1-1.1.1-beta

## Fixes

Fixed 1 bug(s).

- NeoForge 1.20.4 and 1.20.6 client startup crashed in workspaces that contain dispense behaviors. The MCreator
  2026.1 generator registers the generated `<JavaModName>DispenseBehaviors` class on the common NeoForge bus, while its
  `FMLCommonSetupEvent` handler belongs on the mod bus. The plugin now rewrites the generated annotation to
  `@Mod.EventBusSubscriber(bus = Mod.EventBusSubscriber.Bus.MOD)` on 1.20.4 and to
  `@EventBusSubscriber(bus = EventBusSubscriber.Bus.MOD)` on 1.20.6. Regenerate the workspace after updating.

# 2026.1-1.1.0-beta

## New Content

- Native Forge support for `forge-1.16.5`, `forge-1.17.1`, `forge-1.18.2`, `forge-1.19.2`, `forge-1.19.4` and
  `forge-1.20.1`, using the built-in `ForgeConfigSpec` API and `ModLoadingContext` registration.
- NeoForge `1.21.1` and `1.21.8` Port generator definitions, templates and dependency entries.
- Empty `forgeconfigapiport` API implementations for the six Forge generators, used only as conversion compatibility
  markers.
- Generator-aware `api_required` handling in the configuration editor: only Fabric and NeoForge workspaces require the
  Port API.

## Changes

- The configuration element is covered by the Forge, Fabric and NeoForge generator flavors.
- Configuration editor blocks no longer declare `required_apis`; the API prompt is generated by the editor only for
  the platforms that need it.
- Native Forge templates use `ForgeRegistries.ITEMS` and `Arrays.asList`, keeping Forge 1.16.5 Java 8 compatible.
- The Forge compatibility markers use `required_when_enabled: false` and an empty `gradle` block. They add no Gradle
  dependency and no generated code.
- Documentation describes the platform matrix, the conversion marker and the optional Forge metadata entry.

## Known Limitations

- If a workspace keeps the compatibility marker enabled after converting to Forge, the Forge `mods.toml` may contain
  an optional `forgeconfigapiport` entry. It has no build or runtime impact and does not make the Port a required
  Forge dependency.
- Native Forge 1.16.5 targets Java 8, so its generated text list values use `Arrays.asList` instead of `List.of`.
- No configuration screen is registered.
- The package remains a replacement for the original Configuration Files plugin and cannot be enabled together with
  `configuration_files.zip`.

# 2026.1-1.0.0-beta

## New Content

- MCreator 2026.1 branch of the Configuration Files (Forge Config API Port) plugin, with the plugin descriptor limited
  to `2026001` and the build target lowered to Java 21.
- Generator definitions, configuration block templates, procedure templates, mappings and registry templates for
  `neoforge-1.20.4`, `neoforge-1.20.6`, `neoforge-1.21.4` and `fabric-1.21.8`.
- NeoForge configuration registration through
  `fuzs.forgeconfigapiport.neoforge.api.forge.v4.ForgeConfigRegistry`, using the event bus subscriber form that each
  NeoForge generator expects.
- Fabric configuration registration through `fuzs.forgeconfigapiport.fabric.api.v5.ConfigRegistry` and the automatic
  `<JavaModName>Configs` entrypoint injection into `fabric.mod.json`.
- `forgeconfigapiport` ModAPI definitions for the NeoForge `20.4.3`, `20.6.1` and `21.4.3` publications and the Fabric
  `21.8.2` publication, including their runtime version ranges.
- `required_apis` metadata on the configuration editor blocks, so the Blockly editor reports an `api_required` compile
  note while the external API is disabled.
- Independent changelog at the branch root, as required for this source tree.

## Changes

- The configuration element is covered by the Fabric and NeoForge generator flavors. Generator coverage still hides
  the element on generator versions without a `config` definition.
- The generated configuration class imports `java.util.List`, so text list variables compile without relying on the
  import formatter.
- The generated configuration initializer imports the workspace `configuration` package explicitly.
- The Blockly extension script uses the `javabridge.t` translation helper and the Blockly APIs that MCreator 2026.1
  provides.
- The 2026.1 mod element stores the Blockly document through `@BlocklyXML("configs")` and sets the default document in
  the editor, matching the original 2026.1 plugin.
- The plugin compiles against the vendored MCreator 2026.1 API classes and the vendored Log4j API 2.25.3.

## Known Limitations

- The package replaces the original Configuration Files plugin. MCreator 2026.1 bundles `configuration_files.zip`; that
  package, and any older `forge-config-api` package, must be removed or disabled before this plugin is installed. Both
  plugins register the same `config` Blockly editor and `config` mod element type, and MCreator stops during plugin
  initialization when both are enabled.
- No configuration screen is registered. Values are edited in the generated `.toml` file while the game is not
  running.
- The ModAPI definition applies to every workspace that uses a supported generator, even when the workspace contains no
  configuration element.
- Configuration file names are written verbatim (`"<file>.toml"`). Characters that are invalid in a file name are
  rejected by the operating system, not by the plugin.
- The port coordinates are pinned to published releases; updating a generator to a newer port release requires editing
  `apis/forgeconfigapiport.yaml`.
- NeoForge 1.20.4, 1.20.6 and 1.21.4 are marked deprecated by their generators, but remain loadable in MCreator 2026.1.
- The branch does not target the NeoForge 1.21.1 or 1.21.8 generators, the legacy Forge generators, or any Fabric
  generator other than 1.21.8.
